# C2000

`platform/c2000/` fournit un transport MCAN et une persistance en mémoire flash pour le
TMS320F28388D. La pile tourne sur le cœur CM.

Seule la driverlib du cœur CM est nécessaire, plus la Flash API F021 pour la
persistance.

## C2000CanTransport

```cpp
explicit C2000CanTransport(uint8_t nodeId);
```

| Élément | Valeur |
|---|---|
| Périphérique CAN | MCAN0, mode CAN classique |
| Horloge MCAN | 25 MHz |
| Débit | 500 kbit/s |
| Temps de bit | TSEG1 = 7, TSEG2 = 2, SJW = 2 |
| Réception | FIFO 0, 16 éléments de 8 octets |
| Émission | tampon de 16 éléments de 8 octets |
| Horloge | CPUTimer0, libre, période `0xFFFFFFFF`, une microseconde par pas |

Le transport installe 15 filtres sur les COB-ID du nœud :

- trois COB-ID diffusés : `0x000`, `0x080`, `0x100` ;
- douze COB-ID adressés : `0x080`, `0x180`, `0x200`, `0x280`, `0x300`, `0x380`,
  `0x400`, `0x480`, `0x500`, `0x580`, `0x600`, `0x700`, chacun plus le numéro du nœud.

!!! warning "Débit figé"

    Le débit et le temps de bit sont des constantes de `C2000CanTransport.cpp`.
    Modifiez le fichier pour changer de débit.

## C2000Persistence

Les images occupent la banque 0 de la mémoire flash du cœur CM.

| Groupe de paramètres | Secteur | Adresse | Taille |
|---|---|---|---|
| `ParameterGroup_Communication` | 10 | `0x00270000` | `0x4000` |
| `ParameterGroup_Application` | 11 | `0x00274000` | `0x4000` |
| `ParameterGroup_ManufacturerA` | 9 | `0x00260000` | `0x10000` |
| Signature | 12 | `0x00278000` | `0x4000` |

Le secteur 13 est laissé au bootloader. Il contient les métadonnées de l'application, à
partir de `0x0027FF80`.

Deux contraintes matérielles pèsent sur cette implémentation :

- Les commandes flash et leurs boucles d'attente s'exécutent depuis la mémoire vive,
  dans la section `.TI.ramfunc`. Le cœur CM n'a qu'une banque et ne peut pas lire son
  code pendant que la machine d'états flash travaille.
- Le sémaphore de la pompe flash est partagé avec le cœur CPU1. La pile ne le tient que
  pendant l'opération, sinon le cœur CPU1 et le bootloader bloquent.

## Exemple applicatif

`platform/c2000/example/` est un squelette d'application TI.

| Fichier | Rôle |
|---|---|
| `main_cm.cpp` | nœud complet avec `NullRemote` |
| `startup_cm.c` | démarrage du cœur CM |
| `flash.cmd` | script d'édition de liens |
| `Makefile` | compilation |

```cpp
namespace {
CANopen::C2000CanTransport transport(OD_NODE_ID);
CANopen::C2000Persistence persistence;
CANopen::NullRemote remote;
}

CANopen::FullNode canopen(transport, persistence, remote);

int main() {
    CM_init();
    canopen.init();
    while (true) canopen.update();
}
```

## Compiler

```bash
cd platform/c2000/example
make TOOLCHAINPATH=/opt/ti/clang C2000WAREPATH=/mnt/c/ti/C2000/C2000Ware_26_01_00_00
```

| Variable | Défaut | Rôle |
|---|---|---|
| `TOOLCHAINPATH` | `/opt/ti/arm` | racine de la chaîne de compilation TI |
| `C2000WAREPATH` | `/mnt/c/ti/C2000/C2000Ware_26_01_00_00` | racine de C2000Ware |
| `FLASHAPIPATH` | `$(C2000WAREPATH)/libraries/flash_api/f2838x` | Flash API F021 |
| `OD_DIR` | `tests/golden/minimal/cm` | dossier du dictionnaire d'objets |
| `DEBUG` | absent | `1` compile avec `-g -O0` |
| `VERBOSE` | absent | affiche les commandes |

Deux chaînes de compilation sont gérées :

- `tiarmclang`, choisie quand `TOOLCHAINPATH` vaut `/opt/ti/clang` ;
- `armcl`, sinon.

La cible produit `build/firmware.out`, puis `build/firmware.hex`.

!!! warning "Flash API"

    La Flash API F021 est livrée avec C2000Ware, mais absente de son miroir GitHub.
    Installez C2000Ware complet.

## Bi-cœur

`main_cm.cpp` utilise `NullRemote`, donc aucun objet distant n'est servi. Une
application bi-cœur fournit sa propre implémentation de `RemoteObjects`, fondée sur les
structures IPC partagées avec le cœur CPU1.

Le portage d'une application réelle est décrit dans
[migration de sw-motion](../migration-sw-motion.md).
